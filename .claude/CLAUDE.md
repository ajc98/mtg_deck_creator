# CLAUDE.md — MTG Commander Deck Creator

You are helping build a Python CLI project that generates legal Magic: The Gathering Commander decks.

## Core Objective

Build a Commander deck creator that combines:

- Scryfall card data,
- Commander rules,
- color identity validation,
- singleton validation,
- basic land exceptions,
- EDHREC recommendation data,
- vector search,
- role-aware deck construction,
- DuckDB caching/storage,
- clear card-by-card explanations.

## Hard Constraints

- Use Python first.
- Use CLI first.
- Use DuckDB for local storage.
- Do not build Django/React until the deck engine works.
- Do not ignore Commander legality.
- Do not create decks with illegal color identity cards.
- Do not create decks with more or fewer than 100 cards including commander.
- Do not treat vector similarity as the only recommendation signal.
- Do not overload EDHREC. Cache responses locally.

## What the User Wants

The user wants the deck builder to understand that Commander decks are not only about cards with similar text to the commander.

The tool must also consider:

- EDHREC recommendation percentage,
- synergy scores,
- staple cards,
- role balance,
- deck construction fundamentals,
- color identity,
- legal format rules,
- commander-specific strategy,
- owned collection cards if provided.

## First Milestone

Create a working CLI that can:

1. ingest Scryfall Oracle JSON,
2. store cards in DuckDB,
3. validate Commander color identity,
4. fetch/cache EDHREC data for a commander,
5. generate a candidate pool,
6. score candidates,
7. build a legal 100-card deck,
8. explain the result.

## Implementation Style

Use clean, typed, testable Python.

Prefer:

- `pydantic` models for structured objects,
- `typer` for CLI,
- `duckdb` for local DB,
- `rich` for output,
- modular design,
- tests for rules and scoring.

## Warning

A deck generated by simply sorting top vector matches is probably bad.

The generator must fill deck roles and validate the final deck.
